# CryptoBoy · 跨平台产品文档

> 产品名：**CryptoBoy**（界面 i18n：简体中文 / English）  
> 定位：仿照复古「颜色密码破译」小玩具做的 **数字娱乐版**（非商业）  
> 文档状态：产品规格 + 实现对照（进度见 §10 / [PLAN.md](./PLAN.md)）  
> 技术栈：**React + Vite + TypeScript**（已定）  
> 目标形态：Web 优先

---

## 1. 产品定位

把口袋里那台 **颜色密码破译小玩具** 搬到浏览器里玩——项目名 **CryptoBoy**，纯属自娱 / 开源分享，不做商业售卖。

玩家要在 **最多 7 次猜测** 内，破译一组 **4 位颜色密码**。每次猜测后，设备给出位置/颜色反馈，玩家据此进行逻辑推理。

玩法就是玩具上常见的「猜颜色密码」；界面做成复古电子玩具样子：LED 灯阵 + 数码管 + 旋钮，无联网、强调手感与推理乐趣。

### 1.1 目标用户

| 人群 | 诉求 |
| ------ | ------ |
| 儿童（约 5 岁+） | 简单模式、直观提示、失败可重试 |
| 成人 / 益智爱好者 | 进阶模式、间接提示、双人对战 |
| 怀旧 / 玩具爱好者 | 数字版还原玩具外观与操作手感 |

### 1.2 产品目标

1. **玩法跟玩具对得上**：Easy 教学向 / Advanced 汇总向等反馈语义清晰。
2. **外观像那类玩具**：机身 / 面板 / 4×7 LED / 旋钮 / 数码管，数字版娱乐向还原。
3. **操作映射**：旋钮的「转 / 短按 / 长按」在触屏/鼠标上有清晰等价交互。
4. **多端可玩**：至少 Web；按需覆盖手机、平板、桌面。

### 1.3 非目标（本期不做）

- 不做联网排行榜 / 账号体系
- 不做固件逆向或扒取实体机关卡数据
- 不追求与实体机关卡表一一对应（自建生成器即可）
- 不做内购、广告、商业化运营
- **不绑定某一前端框架**——玩法与 UI 规格优先，技术选型服从交付目标

## 3. 核心玩法规则

### 3.1 基本设定

- **密码长度**：4 位
- **密码元素**：若干种颜色（建议起步 6 色，进阶可增至 8 色）
- **是否允许重复色**：建议支持两种规则（关卡配置）
  - Easy：无重复
  - Advanced：中后期可重复
  - 限时挑战：默认可重复，颜色数更高
- **最大尝试次数**：7 次（对应网格 7 行）
- **胜利条件**：某次猜测与密码完全一致（颜色与位置全对）
- **失败条件**：
  - 7 次用尽仍未破译；或
  - **限时挑战**倒计时归零（与用尽次数同类结算）

### 3.1.1 计时规则（已拍板）

| 档位 | 计时 | 结算 | 最佳记录 |
| ------ | ------ | ------ | ---------- |
| Easy | 正计时 `00:00` ↑ | 显示用时 | 按关卡记最短用时 |
| Advanced | 正计时 `00:00` ↑ | 显示用时 | 按关卡记最短用时 |
| 限时挑战 | 倒计时（限额随关卡收紧） | 显示用时=限额−剩余；超时判负 | 同样记最短用时 |

- 关卡号仍由底部数码管显示；用时/剩余在顶栏独立 `mm:ss` 读数，不挤占数码管。
- 打开玩法说明或 `document.hidden` 时暂停；胜负后冻结；重试/新关重置。
- 倒计时最后约 10 秒轻提示（尊重 `prefers-reduced-motion`；短音效跟随静音开关）。

### 3.2 一局流程

```
选择模式 / 难度
    ↓
进入关卡（生成或加载 4 色密码）
    ↓
第 N 行（N = 1…7）进入编辑
    ↓
为 4 个槽位各选一种颜色
    ↓
提交猜测
    ↓
计算反馈 → 点亮提示灯
    ↓
全对？──是──→ 过关动画 / 下一关
    │
    否
    ↓
还有剩余次数？──否──→ 失败音效 / 重试本关
    │
    是
    ↓
进入下一行
```

### 3.3 反馈规则（珠机密码类 · 标准语义）

对每一次猜测，按以下优先级计算提示（同一密码位/猜测位不重复使用）：

| 提示 | 含义 |
| ------ | ------ |
| **绿灯（Black / Exact）** | 颜色正确 **且** 位置正确 |
| **白灯（White / Present）** | 颜色存在于密码中，但位置不对 |
| **无灯** | 该颜色不在密码中 |

计算顺序建议：

1. 先匹配「颜色+位置」完全正确 → 记为绿。
2. 再在剩余位置中匹配「颜色存在」→ 记为白。
3. 其余为无。

> 注意：提示数量与「位」的对应关系因难度模式不同（见下节）。

### 3.4 三档难度与提示展示

| | Easy（简单） | Advanced（进阶） | 限时挑战 |
| -- | ------------- | ------------------ | ---------- |
| 提示 | **按列直示**绿/白/灭 | **汇总**绿白数量，不标列 | 同 Advanced（汇总） |
| 可用颜色数 | 4→5→6 递进 | 6→8 递进 | 6→7→8，整体更难 |
| 重复色 | 不允许 | 中后期允许 | 允许 |
| 计时 | 正计时 | 正计时 | 倒计时，超时判负 |
| 目标用户 | 儿童、入门 | 有经验玩家 | 追求速度的高难玩法 |

**Easy 直接提示（推荐实现）：**

- 每列下方有独立提示位：绿 = 该列正确；白 = 该色在密码中但位置不对；灭 = 不在密码中。
- 注意：严格珠机密码语义下「色在、位不对」并不绑定列；若做「按列直示」，属于 Easy 的简化/教学语义，需在实现中单独定义，并与 Advanced 的标准汇总提示区分。

**Advanced 间接提示（标准汇总语义）：**

- 只告知「几个绿、几个白」，不标明对应哪一列。
- 侧边竖条可点亮对应数量的绿/白指示点。

### 3.5 颜色集合

起步默认 **6 色**；自由练习可扩到 8 色（+ 青 / 粉）。色板与元数据在 `src/domain/colors.ts`（`COLOR_META`）。

| ID | 名称 | 示意色 | 色盲符号（已定义） |
| ---- | ------ | -------- | -------------------- |
| R | 红 | `#E53935` | △ |
| O | 橙 | `#FB8C00` | ○ |
| Y | 黄 | `#FDD835` | □ |
| G | 绿 | `#43A047` | ◇ |
| B | 蓝 | `#1E88E5` | + |
| P | 紫 | `#8E24AA` | ★ |
| C | 青 | `#00ACC1` | ◎ |
| K | 粉 | `#EC407A` | ✦ |

### 3.6 色盲图案模式（已做）

**是什么**：红绿色觉异常时，红 / 绿 / 橙 / 黄等易混；本模式在**保留色块填色**的同时，于每个色点上叠加**唯一几何符号**，让玩家靠形状辨色，而不只靠色相。双通道（色 + 形），不是换主题或灰度。

**开关**：`settings.colorBlindPatterns`（默认 `false`）→ 菜单「色盲图案」；`ColorBlindProvider` 同步 `html[data-color-blind="on"]`。

**覆盖面**：`LedCell`、`ColorPalette`（含设密）、`ResultModal` 揭秘色条；符号来自 `COLOR_META[].symbol`。

**不做**：按色觉类型多套调色板；不改绿白提示点语义。

## 4. 游戏模式

### 4.1 Solo · 闯关模式

- 关卡按序号推进（数码管显示 `001`…）。
- 进度本地持久化；失败只重打当前关，不回退已通关进度。
- Easy / Advanced 进度可分开记录。
- 过关：短音效 + 灯阵庆祝动画 → 自动进入下一关。
- 失败：失败音效 → 展示正确答案（可选）→ 重试本关。

### 4.2 Duo · 双人对战

**本期落地形态**：收进自由练习的「预设答案」开关（同设备本地双人），不单独做 Duo 菜单。

流程：

1. **出题方（P2）**：在练习规则下设置一串 4 色密码。
2. **换手遮罩**：确认后全屏提示，避免破译方偷看。
3. **破译方（P1）**：按当前练习规则猜测，最多 7 次。
4. 破译成功 / 失败后可重试（**保持同一预设密**）；回设置页可改规则或重设密。

对应实体机「拉开顶部天线」的独立入口、局分统计、多设备联机（竞速 / 道具等）**延后**；路由 `/duo` 仍预留。

### 4.3 自由练习（App 增值，实体机无）

- 默认随机一局，**不计闯关进度**；选项会记在本机，下次打开仍保留。
- 可调：
  - **难度系数** 1–5（入门→极限，拖动套用推荐组合）
  - **颜色数** 4–8
  - **是否允许颜色重复**
  - **提示方式**：按列直示 / 绿白汇总
  - **是否限时** + 时限（60/90/120/180 秒）；关闭则为正计时
  - **预设答案（本地双人）**：开启后由同伴设密 + 换手再开局（答案不写 localStorage）
- **快捷复用**：一键填入 Easy / Advanced / 限时挑战的默认规则，仍可再改单项（保留「预设答案」开关状态）。

## 5. 交互设计

### 5.1 主操作：橙旋钮三态

| 实体操作 | 含义 | App 等价交互 |
| ---------- | ------ | -------------- |
| 旋转 | 切换当前槽位颜色 | ① 拖拽旋钮圆周；② 点当前格循环换色；③ 底部色盘点选 |
| 短按 | 光标移到下一槽位 | 点格选中；或点旋钮中心「下一格」 |
| 长按 | 提交本行猜测 | 长按旋钮；桌面也可按 Enter |

原则：**旋钮是主视觉与主操作**，同时提供触屏友好的备选路径，避免「只会转旋钮才能玩」。

### 5.2 编辑态光标

- 当前编辑格：外发光 / 闪烁边框。
- 未填格：暗色空槽。
- 已提交历史行：锁定，不可改。

### 5.3 手势与防误触

- 提交：长按旋钮 ≥ 0.5s，或按 Enter（无独立提交按钮）。
- **确认提交**（设置项，已做）：开启后提交前弹出 UI 确认（非 `window.confirm`）；弹层期间计时暂停；`settings.confirmSubmit`。
- 切换难度 / 模式时，若本局进行中，弹窗确认是否放弃（按需）。

### 5.4 音效

| 事件 | 反馈 |
| ------ | ------ |
| 换色 | 短 tick |
| 移格 | 轻 tick |
| 提交 | 确认音 |
| 过关 | 胜利旋律 |
| 失败 | 低沉音 |

菜单「音效」开/关写入 `settings.sound`（Web Audio；交互前需 resume）。震动档位暂不做。

### 5.5 设置项一览

| 项 | 状态 | 说明 |
| ---- | ------ | ------ |
| 主题 | ✅ | 菜单三色点切换 → `settings.theme` |
| 语言 | ✅ | 简中 / EN → `settings.locale` |
| 音效 | ✅ | → `settings.sound` |
| 进度重置 | ✅ | 清空三档闯关解锁与最佳用时；**保留**主题/语言/音效等；二次确认 |
| 色盲图案 | ✅ | 见 §3.6 → `settings.colorBlindPatterns` |
| 确认提交 | ✅ | → `settings.confirmSubmit`；局内 `ConfirmSubmitModal` |

## 6. 界面信息架构

### 6.1 页面结构

```
主菜单
  ├─ 闯关 Solo（Easy / Advanced / 限时挑战）
  ├─ 自由练习（系数 + 详细选项 + 三档快捷 / 预设答案）
  └─ 帮助与设置
        ├─ 教程 / 主题 / 语言 / 音效 / 色盲图案 / 确认提交
        └─ 进度：重置闯关
对局顶栏：Menu + 模式徽章 + Help（无全局右上角 Help）
（联机 Duo 延后；本地双人见自由练习「预设答案」）
```

### 6.2 游戏桌面布局（竖屏优先）

自上而下：

1. **顶栏**：Menu · 模式徽章 · Help
2. **计时条**：正计时 / 挑战倒计时
3. **灯阵**：4×7 发光格（主视觉）
4. **提示区**：Easy 列下提示 / Advanced 侧边绿白点
5. **底栏**：左数码管（关卡）+ 右旋钮（主控）
6. **色盘**：快速点选颜色

横屏 / 平板：机身居中，两侧留余量，不拉伸破坏比例。

### 6.3 视觉方向、多主题与字体

- 默认「经典原皮」：机身青绿、面板深黑、旋钮亮橙；偏实体玩具摄影感。
- 布局结构共用；主题差异主要靠 CSS 变量（壳 / 面板 / 旋钮 / chrome），见 `src/ui/theme/`。
- 可选主题：经典原皮置顶；其余按色点相似邻近。菜单三色点 = 外壳 + 旋钮 + 主按钮。
- 当前格闪烁对齐旋钮色。LED 游戏色为固定色板（与主题壳色分离）。
- **像素字体**（Press Start 2P）：自托管 `public/fonts/`，经 `injectPixelFont` + `assetUrl` 兼容 Pages `base`。用于品牌标题、机身品牌字、关卡数码管、对局计时数字、顶栏徽章、帮助 `kbd` 等；**结算用时**仍用 `--font-display`，不用像素体。

## 7. 关卡与进度设计

### 7.1 关卡生成策略（自建种子，不依赖厂商数据）

用确定性种子生成，保证同版本可复现、可测：

```
levelSeed = hash(mode, difficulty, levelIndex, appSalt)
password  = generate(levelSeed, colorCount, allowRepeat)
```

难度曲线建议：

| 区间 | Easy | Advanced |
|------|------|----------|
| 前期 | 4 色、无重复 | 6 色、无重复 |
| 中期 | 5–6 色 | 6 色、可重复 |
| 后期 | 6 色 | 8 色、可重复 |

关卡总数可配置为 Easy 100 + Advanced 500（对齐实体宣传），也可先做各 50 关 MVP。

### 7.2 进度存储

键：`code-hack-progress-v2`（见 `src/data/progress.ts`）。示意：

```json
{
  "solo": {
    "easy": { "unlocked": 12, "cleared": 11, "bestTimes": { "1": 12345 } },
    "advanced": { "unlocked": 3, "cleared": 2, "bestTimes": {} },
    "challenge": { "unlocked": 1, "cleared": 0, "bestTimes": {} }
  },
  "settings": {
    "sound": true,
    "confirmSubmit": false,
    "seenTutorial": true,
    "theme": "classic",
    "locale": "zh-CN",
    "customPractice": { "...": "见 customPractice.ts" },
    "colorBlindPatterns": false
  }
}
```

- **重置闯关**：只清空 `solo.*`（解锁 / 通关 / 最佳用时），不改 `settings`。  
- 无需账号；可选后续导出/导入。

### 7.3 统计（可选）

- 总破译次数、最短尝试数、连续通关、各难度完成率。

## 9. 技术选型（待定）

本产品是 **单机益智 UI + 纯前端规则**，不依赖推送、蓝牙、复杂原生能力。  
因此 **Flutter / React / Vue 都能做**；差别主要在交付形态、团队熟悉度、封装成本。

### 9.1 方案对比

| 维度 | React（推荐默认） | Vue | Flutter |
| ------ | ------------------- | ----- | --------- |
| 默认产物 | Web / PWA | Web / PWA | iOS / Android / Web / Desktop |
| 上手与生态 | 最广，组件/动画资料多 | 同样成熟，模板语法友好 | 需 Dart；本机若无 SDK 需先装 |
| 视觉还原 | CSS + Canvas/SVG 足够；旋钮用 pointer 事件 | 同左 | 自绘 Widget，手机端一致性强 |
| 装成 App | Capacitor / Tauri 二次封装 | 同左 | 原生多端是强项 |
| 迭代速度（Web 优先） | 快 | 快 | Web 可跑，但调试链路更重 |
| 适合场景 | 先做出可分享的网页玩具，再考虑上架 | 团队已用 Vue 时优先 | 明确要原生 App 体验、少碰 Web |

### 9.2 推荐结论

| 若目标是… | 建议 |
| ----------- | ------ |
| **尽快玩起来、链接分享、桌面浏览器也行** | **React 或 Vue（Web 优先）**；需要时再 Capacitor 打手机包 |
| **一上来就要上架 App Store / 强原生手感** | Flutter（或 React Native，但本项目自定义机身 UI 多，RN 优势不明显） |
| **团队只会其中一种** | 用最熟的那个——规则层与框架无关 |

> **已选定：React + Vite + TypeScript。**  
> 玩法域（`evaluate` / `generate`）用纯 TS 实现，与 UI 解耦。详细任务见 [PLAN.md](./PLAN.md)。
>
### 9.3 与框架无关的技术要点

| 项 | 建议 |
| ---- | ------ |
| 状态 | 局内状态机：`idle → editing → evaluating → won/lost` |
| 持久化 | `localStorage`（Web）/ 对应平台 KV |
| 音频 | Web Audio 或短音效文件；提供静音开关 |
| 动画 | CSS / motion 库；LED 闪烁、旋钮回弹 |
| 旋钮 | pointer 事件算角度；同时提供点格换色、色盘点选 |
| 适配 | 游戏区竖屏构图居中；桌面留白不拉变形 |
| 测试 | `evaluate` / `generate` 单元测试必覆盖 |

### 9.4 模块划分（Web 示例）

```
src/
  domain/              # 规则、模型、纯函数（零 UI 依赖）
  data/                # 进度、关卡种子
  features/
    menu/
    solo/
    duo/
    settings/
  ui/
    device/            # 机身、灯阵、数码管、旋钮
    theme/
  app/                 # 路由、全局样式
```

`domain` 与 UI 分离，保证规则可测；换 React/Vue/Flutter 只换表现层
